Creative Studio · Nigerian Cultural Intelligence

Add-on architecture and implementation spec for dall-ai (dexway/dall-ai), mapped to the code on main as of 31 Oct 2026.
The ground rule. This is purely an addition. No current page, route, table, navigation item, style or flow changes behaviour or appearance. Ads, Marketing, Harvey, the Assistant & launch kit and the existing Content Creator tabs (Brief → Production, Motion video, Autopilot, Usage) stay exactly as they are. Everything new lives in one new tab group inside Content Creator, new tables with a ci_ prefix and a new lib/culture/ folder.

3. Agent flow (agentic, behind the four tabs)

Agents are workflow steps sharing the gateway, each with its own system prompt, allowed tools and output schema (zod, like lib/creative/schemas.ts). Not nine always-running models.

A. Cultural Intelligence Orchestrator (shared, runs regardless of any business)

StepToolsWrites
Research Director — plans tasks by mode (foundational, scheduled, trend-triggered, on-demand)noneci_research_tasks
Source Scout + Trend Monitor (one agent in v1)Anthropic web search; fetchPublic on the allow-listci_findings (status raw)
Evidence Verifierre-fetch, date check, allow-list checkfinding status verified / rejected with reason
Cultural Analystretrievalmeaning, audience, region, why it's funny/relatable
Knowledge Archivistdedupe (normalised key + embedding similarity later)ci_knowledge new version, status pending_review

Shared knowledge becomes trusted only after admin approval at /admin/culture (or automatic approval for high-confidence evergreen items, behind a setting that defaults off). Research updates the knowledge base, never the model, so every fact can be traced, corrected and rolled back.

B. Commercial Creative Orchestrator (per business, per campaign)

Brief ─► Brand Strategist ─► Cultural Analyst (retrieve trusted + campaign research)
      ─► [if depth ≠ Quick: on-demand research task, results shown as they land]
      ─► Story Architect (3–5 concepts) ─► user approves one
      ─► Production Director (package) ─► QA (scorecard; one auto-fix retry)
      ─► user approves ─► existing content_items / generation_jobs

QA reuses the pattern of Harvey's gate.ts: deterministic checks (claims match catalogue prices and active promotions, no banned phrases, no unfilled placeholders) plus an AI review of language, cultural fit and freshness. A failed check shows the reason, as Harvey does.

C. Learning loop

Performance Analyst (phase 7) reads campaign attribution and reports per audience and format, with sample sizes. It writes to ci_performance, never directly to shared knowledge.

5. Research freshness and sources

LifespanDefault re-verify
Evergreen language / cultureQuarterly
Historical referencesWhen new evidence appears
Recurring social situationsMonthly
Lifestyle / entertainment trendsWeekly
Live viral topicsDaily, permitted sources only
Campaign researchOn demand
Source rules. No scraping of Instagram, Facebook or TikTok; their terms forbid unapproved automated collection. Use Anthropic web search, an admin-managed allow-list of blogs, news and forums whose terms permit it, official APIs when connected, and human-curated entries. Store short excerpts and summaries, never whole articles or posts, and always the source and date.

6. Hand-off into the existing pipeline

  • "Send to Production" creates content_items rows in the brand's current calendar month (or a new "Creative Studio" calendar) with the package's prompt. From there the existing Production tab, budgets, model router and Higgsfield jobs do the work unchanged.
  • Launch-style concepts can prefill a motion_projects brief instead.
  • Each campaign gets a tracking_code; its WhatsApp link is wa.me/<number>?text=…[code]. The inbox already records the first message, so attribution is one new lookup in the existing conversation start handler, read-only for everything else.
  • Ads stays separate. A campaign can later be offered to Ads as a creative, but nothing in Ads changes in this work.

6b. Shared cultural context for the other agents (read-only)

Once trusted knowledge exists, one small helper, cultureContext(workspaceId, topic, max) in lib/culture/retrieve.ts, returns a short block (a few hundred tokens) of relevant trusted references for that business's niche and area. Other agents can opt in by adding that block to their prompt; they keep their own logic, UI and outputs:

AgentWhat it gainsTouch point
Harvey (writer, handler)Outreach and replies that sound local and current, with references a Lagos owner recognisesOne line appended in knowledgeBlock(); Harvey's gate still checks every draft
Motion video (MOTION_SKILL)Launch-video scenes, captions and on-screen lines grounded in recognisable situationsExtra context in motionRequest()
Sales assistant (lib/ai/agent.ts)Tone and expressions only; prices and offers still come only from the catalogueOptional, off by default, per-agent toggle
Creative Director research / calendarContent ideas tied to current cultural momentsContext block in runResearch / draftCalendar

Each hook is guarded: if there's no trusted knowledge or the lookup fails, the agent runs exactly as it does today. These come after phase 2, one agent at a time.

9. Cost and safety controls

  • All calls go through gatewayCall, so existing credits, spend caps and ledgers apply. Deep research counts its web searches.
  • Each workspace gets a daily cap on research tasks; shared scheduled research has its own monthly USD budget set in /admin/culture.
  • Nothing publishes automatically. Every concept and package needs the owner's approval, as in the current Content Creator.
  • Tenant isolation: retrieval takes the workspace id and only ever joins shared + that workspace's rows; tests cover it.
