Dall AI: live test and audit

6 November 2026 · production (dall-ai.vercel.app) · first run with Anthropic credit

Summary. The AI now works in production, and the sales agent behaved well on every safety test. Three things need attention:
  1. The database was paused, which took the whole app offline. It's restored now, but the free plan will pause it again.
  2. Sign-up sometimes creates two businesses for one person.
  3. No business has products in its catalogue yet, so the agent can't quote anything.

2. Problems found

#ProblemImpactFix
1Supabase pauses Dall AI.The whole app goes offline: no chats, sign-ins or orders. Free plan allows 2 active projects, and inactive ones pause.Upgrade Supabase to Pro (about $25/month) before real customers use it. For now react-studio is paused to make room.
2Duplicate businesses at sign-up.3 of 3 owners who signed up twice got two businesses 1–3 seconds apart: heimdall + heimdall-fxef, watercress + watercress-l5h6, mimiko + mimiko-hkw6. Caused by a double-tapped "Continue" button.The server should refuse to create a second business when the user already has one, and the button should disable while saving. Then delete the 3 empty duplicates.
3Empty catalogues.Only "heimdall" has one item. The Thymless agent can't quote a sofa.Add products, or import them from the website (that feature already exists).
4No prompt caching.Every message resends about 4,800 input tokens at full price (cache reads = 0). About $0.017 per AI call.Mark the system prompt and tools as cacheable. Input cost on repeat turns should drop by roughly 70–90%.
5High free-mode daily cap.The free-access cap is 800 AI calls per business per day, about $14/day worst case per business, with no credits charged.Lower FREE_DAILY_AI_CALLS (for example to 150), or switch on paid credits.

4. Costs observed

Each customer message used 1–2 AI calls of about 4,700–5,000 input and 150–310 output tokens, costing $0.016–0.019 per call. This test run cost about $0.09. Most of that is input tokens repeated on every turn, which is what caching (problem 4) fixes.
